UNIT 01 Introduction to Android

Android OS, History, Android Studio, AVD, Project Types, App Categories — All covered with full marks answers.

Q1 Define Android OS. Explain the features of Android in detail. 10 Marks ▼
Definition: Android is a mobile operating system (OS) based on a modified version of the Linux kernel and other open-source software, designed primarily for touchscreen mobile devices such as smartphones and tablets. It is developed and maintained by Google and was first released commercially in 2008.
Key Facts
  • Android is open-source — its source code is freely available under Apache License.
  • It is the world's most used mobile OS — over 3 billion active devices.
  • Apps are primarily written in Java or Kotlin.
  • Apps are distributed through the Google Play Store.
Features of Android — Detailed
1. OPEN SOURCE
Android is built on open-source software. Anyone — developers, manufacturers, and companies — can freely download, use, modify, and distribute Android code. This is why you see Android on phones from Samsung, OnePlus, Xiaomi, Motorola, and hundreds of other brands. They all customize Android to their taste.
2. MULTI-TASKING
Android supports running multiple applications simultaneously. You can listen to Spotify while browsing Instagram and also have WhatsApp running in background. The OS intelligently manages memory and CPU between these tasks.
3. CONNECTIVITY
Android supports a wide range of connectivity options: Wi-Fi, Bluetooth, 4G LTE, 5G, NFC (Near Field Communication), USB, GPS, and mobile data. Apps like Google Pay use NFC to make payments by tapping the phone.
4. RICH MULTIMEDIA SUPPORT
Android natively supports audio formats (MP3, AAC), video formats (MP4, AVI), and image formats (JPEG, PNG, GIF). Apps like VLC, YouTube, and Spotify work because Android's media framework supports these formats built-in.
5. GOOGLE PLAY STORE
Android has an official marketplace with 3+ million apps. Users can download, update, and purchase apps securely. Google Play Protect scans apps for malware automatically.
6. CUSTOMIZABLE USER INTERFACE
Android allows deep customization — change launcher, add widgets, use live wallpapers, change icon packs. Samsung's One UI and Xiaomi's MIUI are custom Android skins — they look completely different but are still Android underneath.
7. PUSH NOTIFICATIONS
Apps can send real-time notifications even when the app is not open. Example: WhatsApp message notification, Gmail new email alert, Swiggy order update — all delivered via Android's notification system.
8. LOCATION SERVICES (GPS)
Android integrates Google Maps and GPS. Apps like Uber, Ola, Zomato, and Google Maps use this to track location, provide directions, and show nearby restaurants or drivers.
9. SECURITY FEATURES
Android includes screen lock (PIN, pattern, fingerprint, face unlock), app permissions (camera, contacts, storage), Google Play Protect (malware scanner), and encryption of device data.
10. WIDE HARDWARE SUPPORT
Android runs on phones, tablets, smartwatches (Wear OS), smart TVs (Android TV), cars (Android Auto), and even refrigerators. The same OS powers a ₹5000 Redmi phone and a ₹1,50,000 Samsung foldable.
Remember: Android = Linux Kernel + Open Source + Java/Kotlin + Google Play. This is the one-line definition perfect for exams.

Q3 What is Android Studio? Explain its features and installation process on Windows. 10 Marks
Android Studio is the official Integrated Development Environment (IDE) for Android application development. It was launched by Google in May 2013 at Google I/O. It is based on IntelliJ IDEA by JetBrains and replaced Eclipse as the standard Android IDE. It supports Java and Kotlin programming languages.
Features of Android Studio
  • Smart Code Editor: Provides intelligent code completion (autocomplete), syntax highlighting, refactoring tools, and real-time error detection as you type.
  • Visual Layout Editor: A drag-and-drop UI designer to build app screens visually without manually writing all XML code. Shows live preview of the design.

  • Gradle Build System: Automates the build process — compiles code, manages dependencies (libraries), and packages the APK file.
  • Logcat: A real-time log viewer showing system messages, print statements, and error/exception stack traces from the device or emulator.
  • Android Profiler: Monitors CPU usage, memory allocation, battery consumption, and network activity in real-time while the app is running.
  • Git Version Control: Built-in support for Git — commit code, manage branches, push to GitHub directly from the IDE.
  • Firebase Integration: Easily connect your app to Firebase services (database, auth, analytics) with a wizard-based setup.
  • Multi-window & Multi-device Preview: Preview layouts on different device screens (phone, tablet, watch) simultaneously.
  • Lint Tool: Scans your code for potential bugs, performance issues, and style violations before you even run the app.

Q4 What is AVD? How to create an AVD? List and explain Android Tools. 8 Marks
AVD = Android Virtual Device. It is an emulator configuration that defines the hardware and software characteristics of an Android device that you want to simulate on your computer. Using AVD, you can test your Android app on a virtual phone or tablet without needing a real physical device.
Why Use AVD?
  • Test on multiple screen sizes and Android versions without buying multiple phones.
  • Simulate hardware features like GPS, camera, accelerometer, incoming calls, and SMS.
  • Debug apps using Logcat while the emulator runs.
  • Test edge cases like low battery, no network, and airplane mode.
Steps to Create an AVD
  1. Open Android Studio.
  2. Go to Tools → Device Manager (or click the phone icon on the right sidebar).
  3. Click "Create Device" or "Create Virtual Device".
  4. Choose a hardware profile — e.g., Pixel 6 (select screen size and resolution).
  5. Select a System Image — choose an Android version (e.g., Android 13 / API 33). Download if not already done.
  6. Configure AVD settings: Give it a name, set RAM and internal storage.
  7. Click Finish — the AVD is created.
  8. Click the ▶ Play button next to the AVD to launch the emulator.

Q5 Differentiate between Native, Hybrid, and Web Applications with examples. 10 Marks
1. Native Application
A Native App is built specifically for one platform using that platform's official language and tools. Android native apps use Java or Kotlin. iOS native apps use Swift or Objective-C.
  • Best Performance: Directly compiled to machine code — fastest execution.
  • Full Device Access: Full access to camera, GPS, accelerometer, Bluetooth, NFC, fingerprint, etc.
  • Best User Experience: Follows platform design guidelines — feels natural to the user.
  • Offline Support: Works without internet once installed.
  • Expensive: Separate development for Android and iOS — doubles cost and time.
  • Examples: Gmail (native Android), WhatsApp, Google Maps, Instagram
2. Hybrid Application
A Hybrid App is built using web technologies (HTML, CSS, JavaScript) wrapped inside a native container (WebView). The same codebase runs on both Android and iOS. Tools like React Native, Flutter, Ionic, Xamarin are used.
  • Cross-platform: One codebase for both Android and iOS — saves time and money.
  • Medium Performance: Slightly slower than native, faster than pure web apps.
  • Partial Device Access: Can access camera, GPS, etc. through plugins/bridges.
  • Available on App Stores: Published on Play Store and App Store like native apps.
  • Examples: Facebook (React Native), Instagram (partial), Alibaba Xianyu (Flutter)
3. Web Application
A Web App runs in a mobile browser. It is built with HTML, CSS, and JavaScript and accessed via a URL. It does NOT get installed from the Play Store.
  • Platform Independent: Works on any device with a browser — no installation needed.
  • Slowest Performance: Depends entirely on browser and internet speed.
  • Limited Device Access: Cannot access most hardware features like GPS (limited), camera (via getUserMedia), Bluetooth, NFC.
  • No App Store: Not available on Play Store — accessed via URL only.
  • Cheapest to Build: One codebase for all platforms.
  • Examples: Gmail web (mail.google.com), Twitter/X web, Google Docs

Build and Run Process

Steps to Build and Run
  1. Open your project in Android Studio.
  2. Write or edit your code in the editor.
  3. Connect a physical device via USB (enable Developer Options + USB Debugging) OR launch an AVD emulator.
  4. Click the green Run ▶ button or press Shift + F10.
  5. Android Studio runs Gradle to compile and build the APK.
  6. The APK is installed on the selected device/emulator.
  7. The app launches automatically — test and debug!
Best Practices in Android Programming
  • Use MVVM Architecture: Separate UI (View), business logic (ViewModel), and data (Model) for clean, testable code.
  • Never block the Main Thread: All network calls, database operations, and heavy tasks must be done on background threads using Coroutines or AsyncTask.
  • Use ViewBinding: Avoid findViewById() — use ViewBinding for type-safe, null-safe access to views.
  • Store strings in strings.xml: Never hardcode text in Java/Kotlin. Use resource files for easy localization (multi-language support).
  • Request minimum permissions: Only request permissions the app actually needs. Unnecessary permissions reduce user trust.
  • Handle Null Properly: Use Kotlin's null safety (? operator) or check for null in Java to avoid NullPointerException crashes.
  • Use RecyclerView over ListView: RecyclerView is more efficient for large lists — it recycles views instead of creating new ones.
  • Use proper naming conventions: camelCase for variables, PascalCase for classes, UPPER_SNAKE_CASE for constants.
  • Test on multiple devices: Use AVD to test different screen sizes and Android versions to ensure compatibility.
  • Use version control (Git): Commit code regularly, use branches for features, and backup on GitHub.

Q1 List and explain the building blocks of an Android Application. Also explain the anatomy of an Android application. 10 Marks
Android applications are made up of 4 core building blocks (components). These are the fundamental units of an Android app. Each component serves a different purpose and has its own lifecycle. They are all declared in the AndroidManifest.xml file.
┌──────────────────────────────────────────────────┐ │ Android Application │ │ │ │ ┌─────────────┐ ┌─────────────────────┐ │ │ │ Activity │ │ Service │ │ │ │ (UI Screen) │ │ (Background Task) │ │ │ └─────────────┘ └─────────────────────┘ │ │ │ │ ┌──────────────────────┐ ┌──────────────────┐ │ │ │ Broadcast Receiver │ │ Content Provider │ │ │ │ (System Events) │ │ (Share Data) │ │ │ └──────────────────────┘ └──────────────────┘ │ │ │ │ ┌────────────────────────────────────────────┐ │ │ │ AndroidManifest.xml │ │ │ │ (Declares all components + permissions) │ │ │ └────────────────────────────────────────────┘ │ └──────────────────────────────────────────────────┘
1. Activity
What it is
An Activity represents a single screen with a user interface. Every screen you see in an Android app is one Activity. An app can have multiple Activities linked together.

Real Example: In Instagram — the Home Feed screen is one Activity, the Profile screen is another Activity, and the Camera screen is a third Activity. Each has its own layout and logic.
2. Service
What it is
A Service runs in the background without any UI. It performs long-running operations even when the user is not interacting with the app.

Real Example: When you play music on Spotify and switch to WhatsApp — the music keeps playing. That is a Foreground Service. When Gmail syncs new emails in the background — that is a Background Service.
3. Broadcast Receiver
What it is
A Broadcast Receiver listens to system-wide announcements (broadcasts) and responds to them. It doesn't display a UI (usually just shows a notification or triggers some action).

Real Example: When your phone battery drops to 15%, Android broadcasts a "BATTERY_LOW" intent. Your battery warning notification app has a BroadcastReceiver that catches this and shows an alert to the user.
4. Content Provider
What it is
A Content Provider manages and shares data between different applications. It provides a standard interface to access structured data (usually from a database).

Real Example: The Contacts app on your phone uses a Content Provider to store contact data. WhatsApp, Gmail, and Truecaller all query this same Content Provider to read your contacts — they don't have their own contact database!

Q2 What is Context in Android? Explain the types of Context with their functionalities. 8 Marks
Context is an abstract class in Android that provides access to application-specific resources, classes, and operations such as launching activities, sending broadcasts, accessing databases, and loading resources. It is the "handle" to the current state of the application environment. Almost every Android operation requires a Context object.
Simple Analogy
Real-life analogy
Think of Context like a hotel room key card. The key card gives you access to your room (resources), the gym (services), the restaurant (system services) — but only within the hotel (application). Without the key card (Context), you can't access anything.
Types of Context
1. Application Context
Application Context — getApplicationContext()
This Context is tied to the lifecycle of the entire application. It lives as long as the app is running — it is created when the app starts and destroyed only when the app completely closes.

Use it when: You need a Context that will outlive the current Activity — for operations that should persist across the entire app lifetime.
Functionalities of Application Context:
  • Starting a Service (that should run beyond one Activity)
  • Accessing and managing SharedPreferences
  • Accessing the SQLite Database
  • Registering a BroadcastReceiver
  • Sending Broadcasts across the app
  • Accessing application-wide Resources (strings, colors)
  • Getting System Services like ConnectivityManager, LocationManager
2. Activity Context
Activity Context — this (inside Activity)
This Context is tied to the lifecycle of a specific Activity. When the Activity is destroyed (user presses Back or calls finish()), this Context is also destroyed. Using Activity Context after it's destroyed causes memory leaks.
Functionalities of Activity Context:
  • Showing Toast messages on screen
  • Showing AlertDialog, ProgressDialog
  • Inflating XML layouts using LayoutInflater
  • Starting another Activity
  • Accessing views and UI components
  • Starting an Activity for result

An Activity is a single screen with a User Interface (UI). It represents one focused thing the user can do — like reading emails, taking a photo, or filling a form. An Android app is a collection of Activities. Each Activity has its own lifecycle managed by the Android OS.

In the Amazon Shopping App:

Each is a separate Activity. When you go back, the previous Activity resumes.

Q4 What is a Service in Android? Explain its types and complete lifecycle with a diagram. 10 Marks
A Service is an Android component that performs long-running operations in the background without a user interface (UI). Services continue to run even when the user switches to another app. They are used for tasks that should not block the main thread and don't require user interaction.
Real-life Examples of Services
• Playing music on Spotify while browsing Instagram → Foreground Service
• Gmail syncing emails automatically every few minutes → Background Service
• Google Maps tracking location even when screen is off → Foreground Service
• WhatsApp checking for new messages → Background/Bound Service
Types of Services
1. FOREGROUND SERVICE
A Foreground Service runs a task that the user is actively aware of. It must show a notification in the notification bar. The OS gives it higher priority — it is less likely to be killed when memory is low.

When to use: Music player, navigation, fitness tracking, file downloads
Example: Spotify shows "Now Playing: Song Name" notification → that IS the foreground service notification.
2. BACKGROUND SERVICE
A Background Service runs operations without any UI or notification. The user doesn't know it's running. Since Android 8.0 (Oreo), background services have heavy restrictions — OS may kill them to save battery.

When to use: Syncing data, updating local database, fetching configuration
Note: Use WorkManager for deferred background tasks in modern Android development.
3. BOUND SERVICE
A Bound Service allows other components (Activities or other Services) to bind to it and interact with it — like a client-server relationship. The service runs only as long as a component is bound to it. When all clients unbind, it is destroyed.

When to use: Music player that Activities control (play, pause, skip)
Example: A music app where the Activity sends "play", "pause" commands to the Service.

Q5 What are Intents? Explain Explicit and Implicit Intents with examples. 10 Marks
An Intent is a messaging object in Android used to request an action from another app component. It acts as a bridge between components — Activities, Services, and BroadcastReceivers. The word "Intent" literally means "intention" — you declare what you intend to do, and Android figures out how to do it.
What can Intents do?
  • Start a new Activity (navigate to another screen)
  • Start a Service (trigger a background task)
  • Deliver a Broadcast (send a message to the whole system)
  • Pass data between components (using extras)
Type 1: Explicit Intent
Explicit Intent directly specifies the component (Activity/Service) to be started by its class name. You know exactly which component you want to launch — it's inside your own app.
  • Used to navigate between your own app's screens.
  • You explicitly name the target Activity class.
  • Android does NOT need to figure out the target — you've already told it.
Example: Going from MainActivity to ProfileActivity
// In MainActivity.java — going to ProfileActivity Intent intent = new Intent(this, ProfileActivity.class); // Optionally pass data to ProfileActivity intent.putExtra("username", "Tejas"); intent.putExtra("age", 22); startActivity(intent); // Launch ProfileActivity // ---- In ProfileActivity.java — receiving data ---- String name = getIntent().getStringExtra("username"); // "Tejas" int age = getIntent().getIntExtra("age", 0); // 22
Type 2: Implicit Intent
Implicit Intent does NOT specify a particular component. Instead, it declares an action to perform — Android finds the best app installed on the device to handle that action. If multiple apps can handle it, Android shows a chooser dialog.
  • Used to interact with other apps on the device.
  • Android uses the Intent Filter in the Manifest to match the right app.
  • If no app can handle the action, the app may crash — always check!
// 1. Open a URL in Browser Intent i = new Intent(Intent.ACTION_VIEW, Uri.parse("https://google.com")); startActivity(i); // 2. Make a Phone Call Intent call = new Intent(Intent.ACTION_DIAL, Uri.parse("tel:9876543210")); startActivity(call); // 3. Share text with any app Intent share = new Intent(Intent.ACTION_SEND); share.setType("text/plain"); share.putExtra(Intent.EXTRA_TEXT, "Check this out!"); startActivity(Intent.createChooser(share, "Share via")); // 4. Open Camera Intent cam = new Intent(MediaStore.ACTION_IMAGE_CAPTURE); startActivityForResult(cam, 100);

Q6 Explain AndroidManifest.xml in detail with its common settings. 8 Marks
AndroidManifest.xml is the most important configuration file in any Android project. It is located at the root of the project (app/src/main/). It tells the Android OS everything about your application — its components, permissions, minimum SDK version, theme, and app metadata. Q2 What is SQLite Database? Explain how data is stored. List all methods and operations with examples. 10 Marks
SQLite is a lightweight, serverless, self-contained relational database engine that is built into every Android device. Unlike traditional databases (MySQL, PostgreSQL) that require a separate server to run, SQLite is embedded directly within the Android application as a .db file on the device's internal storage.
Key Characteristics of SQLite
  • Serverless: No separate database server process — runs inside your app.
  • Zero Configuration: No setup or installation required — just create a class and start using it.
  • Transactional: Supports ACID transactions (Atomic, Consistent, Isolated, Durable).
  • Small Footprint: The entire library is less than 600KB.
  • Standard SQL: Supports standard SQL queries (SELECT, INSERT, UPDATE, DELETE).

Q5 How is Networking done in Android? Explain all HTTP Methods in detail. 10 Marks
Networking in Android allows apps to communicate with remote web servers over the internet to send and receive data. This is how apps like Instagram load photos, WhatsApp sends messages, and Zomato shows nearby restaurants — all through network/API calls.
Rules for Android Networking
  • Add INTERNET permission in AndroidManifest.xml — without this, all network calls fail.
  • Never do network calls on the Main (UI) Thread — it causes ANR (App Not Responding). Use background threads, AsyncTask, or Kotlin Coroutines.
  • Handle exceptions — network can fail anytime (no signal, server down, timeout).
<!-- AndroidManifest.xml --> <uses-permission android:name="android.permission.INTERNET" />
HTTP Methods — Explained in Detail
1. GET — Retrieve/Fetch Data
The GET method is used to read/retrieve data from the server. It does NOT modify any data on the server. Parameters are sent in the URL itself.

Example: Fetching the list of all products from an e-commerce API.
Request: GET https://api.myshop.com/products
Response: [{"id":1,"name":"Shirt","price":499}, {"id":2,...}]
2. POST — Create/Submit New Data
The POST method is used to send new data to the server to create a new resource. Data is sent in the request body (not URL). Used for login, registration, placing orders.

Example: Registering a new user.
Request: POST https://api.myapp.com/users
Body: {"name":"Tejas","email":"tejas@gmail.com","password":"12345"}
3. PUT — Update/Replace Entire Resource
The PUT method is used to completely update/replace an existing resource. You send the full updated data for that resource. If the resource doesn't exist, it may create one.

Example: Update user profile with all new values.
Request: PUT https://api.myapp.com/users/5
Body: {"name":"Tejas Kumar","email":"new@gmail.com","age":23}
4. PATCH — Partially Update a Resource
The PATCH method is used to partially update a resource — you only send the fields that changed, not the full data.

Example: Update only the email of user ID 5.
Request: PATCH https://api.myapp.com/users/5
Body: {"email":"newemail@gmail.com"} (only the changed field)
5. DELETE — Remove a Resource
The DELETE method is used to delete a resource from the server permanently.

Example: Delete a product from the catalogue.
Request: DELETE https://api.myshop.com/products/10
Response: {"message": "Product deleted successfully"}

Q6 What is a RESTful Web Service? Explain its principles and working with an example. 10 Marks
REST (Representational State Transfer) is an architectural style for designing networked applications. A RESTful Web Service is a web service that follows the REST principles to enable communication between a client (like an Android app) and a server over HTTP. It is the most widely used approach for building APIs today.
Simple Analogy
REST is like ordering food at a restaurant
You (Client/Android App) look at a menu and place an order (request).
Waiter (REST API) takes your order to the kitchen (server).
Kitchen (Server + Database) prepares the food (processes data).
Waiter brings your food back (response — usually in JSON format).
You don't need to know HOW the kitchen works — just what to order!
Principles / Constraints of REST
  • 1. Client-Server Architecture: The client (app) and server are separate and independent. The client handles the UI; the server handles data. They communicate only through API calls.
  • 2. Stateless: Each request from the client to the server must contain ALL information needed to process it. The server does NOT store session info between requests. Every request is independent.
  • 3. Cacheable: Responses can be cached on the client side to improve performance and reduce server load.
  • 4. Uniform Interface: Uses standard HTTP methods (GET, POST, PUT, DELETE) and standard URIs. Makes the API predictable and easy to use.
  • 5. Resource-Based: Everything is treated as a "resource" identified by a unique URI. Example: /users is the resource for all users; /users/5 is the resource for user with ID 5.
  • 6. Layered System: Client doesn't know if it's connected directly to the server or a load balancer, cache server, or proxy.

Q7 What is a Web API? Why is it used? How to use a Web API in Android? List popular Web APIs. 10 Marks
Web API (Application Programming Interface) is a set of rules, protocols, and tools that allows different software applications to communicate with each other over the internet. In Android development, a Web API is the interface through which your Android app communicates with a remote server to get or send data.
Simple Analogy
API is like a waiter in a restaurant
You (Android App) are the customer sitting at the table.
The kitchen (Server) has the food (data/functionality).
The waiter (API) takes your order (request) to the kitchen and brings back your food (response).
You never go to the kitchen directly — you always go through the waiter (API)!
Why are Web APIs Used in Android?
  • Real-time Data: Fetch live weather, news, cricket scores, stock prices that change constantly.
  • User Authentication: Login with Google, Facebook, or your own backend — securely handled by API.
  • Payment Processing: Razorpay, Stripe, PayU APIs handle payments — your app doesn't handle card details directly.
  • Cloud Storage: Upload/download photos, files to/from cloud servers via APIs.
  • Third-party Services: Show a map (Google Maps API), send SMS (Twilio API), translate text (Google Translate API).
  • Sync Data Across Devices: One database on the server, all users' devices get the same data through the API.
  • Reduce App Size: Logic stays on the server — app just calls the API instead of having complex code locally.
How to Use a Web API in Android — Step by Step
  1. Add INTERNET permission in AndroidManifest.xml.
  2. Add an HTTP library to build.gradle — Retrofit or Volley are most popular.
  3. Get the API documentation — find the endpoint URL, required headers (like API Key), and request/response format.
  4. Make the API call on a background thread (not main thread!).
  5. Parse the JSON response into Java objects.
  6. Update the UI with the fetched data.
